# 移动端第一版设计

## 目标与授权范围
续接已完成的浏览器插件，在 D:/code/behavior-rules/apps/mobile 创建 Flutter 应用。Android 交付可安装调试 APK；iOS 复用界面并接入真实 Screen Time 平台适配，未构建和未验证的部分明确标注。默认中文、本机保存，无账号、服务器或跨端同步。用户已要求常规实现自主决定，先本地体验，暂不发布。

## 产品行为
- 我的规则、规则模板、触发记录、运行与备份四个主要页面。规则编辑采用“当我打开这些应用，在这些时候，帮我……”的表达；高级设置含例外应用及优先级。
- 一条规则可选择多个已安装应用，作为共享额度的应用组；例外从该组排除。Android 不允许选择本工具、桌面、系统设置、电话等必要系统组件。
- 三种 Android 动作：仅提醒（非全屏提示，可继续）；等待（全屏遮罩，倒计时后点继续）；直接拦截（遮罩，点击返回桌面）。返回桌面不声称结束其他应用进程。支持自定义提示语/按钮文字、效果预览、启停、15分钟临时放行。
- 默认没有启用规则。保存后立即更新。提醒确认及等待完成只针对本次前台访问，真正离开目标应用后失效；权限弹窗/键盘等临时系统窗口不应重复触发。
- 时段按本机时区；日期用0=周日…6=周六；开始包含，结束不含；开始=结束为全天，跨午夜按开始日归属。额度0表示直接处理，大于0达到分钟额度后处理。每条规则独立合计组内前台使用，零点清零。锁屏、后台、等待/拦截遮罩期间不计时；提醒和临时放行期间计时。服务断连和重启期间不补计未知时间。
- 先排除例外/未到时段/未到额度/临时放行，再按 block > delay > remind、priority大者、createdAt早者、id排序。界面说明生效规则。
- 数据持久化：规则、当日及最近8天用时、最多300条日志、临时放行绝对到期时间。单次确认与计时采样不跨服务重启；等待持久化截止时间，但仅恢复到对应当前应用。导入严格校验版本/平台/数量/范围，不接受任意未知动作；最大200规则、每规则100目标、100例外、2MiB。导出仅规则，导入确认后替换规则并重置用时与放行。

## 平台方案
Flutter负责界面/校验/编辑及平台能力展示；Android Kotlin是执行状态唯一写入方，通过 MethodChannel 连接。AccessibilityService 只监听前台窗口包名，不读取界面文字；采用 TYPE_ACCESSIBILITY_OVERLAY 展示干预，GLOBAL_ACTION_HOME返回桌面。运行页解释用途并由用户亲自开启无障碍服务；状态区分已授权和服务已连接。权限撤销、锁屏、重启会停止/恢复监测；不得伪称厂商后台限制已彻底解决。不申请Root、设备管理器，不阻止用户退出/卸载。
iOS应用目标使用系统FamilyActivityPicker不透明token集合，不能用Android包名充当iOS标识。适配 FamilyControls / ManagedSettings / DeviceActivity，能力表只显示实现的动作，提醒/等待不假装与Android等效；未完成签名/entitlement/扩展配置时清楚显示限制。Windows无法执行Xcode编译和iPhone真机测试。

## 边界与验收
应用启动到遮罩存在系统事件延迟；画中画/分屏和厂商省电策略需真机验证；这不是不可绕过的家长控制。仅本地调试APK，不申请上架。
验收：Dart校验/编辑widget测试；Kotlin规则引擎时段、额度、跨午夜、例外、冲突、临时放行与异常输入测试；构建APK并检查清单；模拟器可用则验收授权、目标切换、锁屏、三种动作与重启。无设备的项目明确标注未验证，不用模拟数据冒充实机执行。
