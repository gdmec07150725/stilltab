## iOS使用与限制
该目录含实际Swift API适配和三个扩展源码，并已接入 Xcode 工程。Runner 依赖并嵌入 BehaviorMonitor、BehaviorShield、BehaviorShieldAction 三个 appex；Runner、Monitor、Shield 编译共享 BehaviorStore.swift，Runner 编译 BehaviorPlatform.swift。四个目标均配置 Debug、Release、Profile、iOS 16 最低版本、独立 bundle ID、Family Controls 与同一个 App Group entitlement。能否工作必须在Mac上构建、配置开发团队与授权后用iPhone验证。没有这些环境时不交付IPA，不声称iOS可用。

1. 在Mac安装Flutter/Xcode，打开apps/mobile/ios/Runner.xcworkspace（执行flutter pub get及相应iOS依赖准备）。
2. 为Runner、BehaviorMonitor、BehaviorShield、BehaviorShieldAction四个target选择开发团队，启用Family Controls和App Groups。App Group必须一致，当前标识为group.com.behaviorrules.mobile；若改标识，应同步Shared/BehaviorStore.swift和四份entitlements。实际签名需要该团队拥有的bundle ID。
3. 工程已配置三个 appex 的嵌入、目标依赖及源码归属；在 Xcode 检查四个目标的 Signing & Capabilities，按自己的团队调整 bundle ID，并进行首次编译。Swift 编译、签名有效性和扩展加载尚未验证。
4. 真机安装后，在“运行与备份”主动授权屏幕使用时间，再用系统选择器选择应用。首版只支持全天屏蔽；模板/条件根据能力表收敛。
5. 调整或停用规则从本App操作。用户保留删除App、撤回个人授权的能力。

系统选择token不可替换为Android包名，也不能保证跨设备恢复。iOS JSON导出保留本机选择ID；导入到别的设备会拒绝缺失的选择，需重新选择应用。临时放行到期的系统回调在设备使用时触发，不承诺毫秒精度。尚未通过真机验证的API行为、token有效性、扩展启动与授权撤销必须在后续验收中检查。

## 工程接线检查

`node scripts/configure-ios.cjs --check` 仅解析 Xcode 项目并检查目标、三种构建配置、源码文件、entitlements、最低系统版本以及 Runner 的扩展依赖与嵌入关系；记录在 `work/ios-project-check.json`。依赖安装命令为 `npm install --prefix work/ios-project-tools xcode@3.0.1`。不带 `--check` 可重新应用接线配置。此检查不运行 Xcode，不代表 Swift 编译、Apple 签名或 iPhone 真机验证通过。
