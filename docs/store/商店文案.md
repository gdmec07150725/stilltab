## 完整功能描述（Chrome / Edge 通用）

打开网页之前，给自己留一个停下来的机会。

「停一下 · 网页行为规则」帮助你为常逛的网站设定浏览规则：轻轻提醒、等待几秒再继续，或在指定条件下显示拦截页面。你决定哪些网站受影响，也决定规则什么时候生效。

三种处理方式：

- 仅提醒：在网页上显示你写下的提醒，仍可浏览。
- 等待后放行：先显示倒计时，结束后点击按钮继续。
- 直接拦截：显示拦截遮罩，可以关闭当前标签页，或从插件中管理规则。

按自己的习惯设置：

- 匹配整个网站、某段网址路径，或一个具体页面。
- 按星期和时间段启用，支持跨午夜时段。
- 设置每日浏览额度，达到额度后再执行提醒、等待或拦截。
- 为需要正常访问的页面添加例外。
- 临时放行一条规则 15 分钟，到期自动恢复，也可提前结束放行。
- 自定义提醒文字和按钮文字，使用模板快速创建规则。
- 从工具栏查看当前页面状态，查看最近的规则触发记录。
- 导出、导入规则 JSON，方便备份或手动迁移。

本地运行，不需要注册账号。扩展会在本机读取网页地址、活动标签页和窗口状态，计算符合规则的前台浏览时间，并保存规则、每日用时、临时放行和最近触发记录。这些数据不会由扩展上传给开发者或第三方。触发记录不保存网址的查询参数和锚点；你主动保存的精确网址规则仍可能包含这些信息。导出的备份只包含规则设置。

适用于桌面浏览器的普通 HTTP / HTTPS 网页。浏览器设置页、扩展商店等受保护页面不能执行规则。仅累计前台活动网页的符合条件用时；等待、拦截、后台标签页及锁屏期间不累计。

这是一款自我管理工具。拦截通过网页遮罩实现，页面可能在遮罩出现前加载内容或发起请求；关闭或移除扩展即可停止限制。首次安装没有自动启用的示例规则，可以从一条提醒开始。

## 单一用途说明

帮助用户通过自行设置的网站、页面、时段与每日用时规则管理浏览习惯，在条件满足时显示提醒、等待倒计时或访问遮罩。网址判断、计时、规则管理、触发记录及临时放行均服务于这一用途，在用户设备上完成。

## 权限理由

以下理由对应已检查的 Manifest V3 权限。提交前须与最终 manifest 一致；移除的权限不再填报。

| 权限 | 可提交的理由 | 实际源码依据 |
| --- | --- | --- |
| storage | 在本机保存用户建立的规则、每日用时、最近触发记录及临时放行到期时间，并在当前浏览器会话中保存等待和确认状态。未使用云同步存储。 | background.ts：storage.local / storage.session |
| scripting | 在扩展安装、更新和浏览器启动时，为已经打开且允许注入的普通网页加载扩展自带的内容脚本，使现有页面也能应用用户规则。仅执行安装包内的 content.js。 | background.ts：injectExisting / executeScript |
| alarms | 定期唤醒扩展后台，核对时段、规则与临时放行到期状态，并更新已打开网页上的提示。 | background.ts：reconcile alarm（30 秒） |
| webNavigation | 识别单页应用的历史地址变化和网址锚点变化，及时重新匹配规则，重置相应页面的等待与确认状态。 | background.ts：onHistoryStateUpdated / onReferenceFragmentUpdated |
| idle | 识别系统锁屏状态，暂停锁屏期间的浏览用时统计，解锁后重新判断规则。无需读取键盘输入或鼠标内容。 | background.ts：idle.queryState / onStateChanged |
| http://*/* 与 https://*/* 主机权限 | 用户可以为任意普通网站创建规则。扩展需要在这些网页上读取地址、执行安装包内的内容脚本，自动显示提醒或遮罩并计算前台用时；这需要持续生效，不能只在点击工具栏后短暂启用。网页地址只用于本机规则判断和记录，不上传。 | manifest.json：host_permissions / content_scripts；background.ts / content.ts |

### tabs 权限审核结论

初始 manifest 另有 tabs 权限，源码用它读取标签页 URL，但已有 HTTP / HTTPS 主机权限能读取匹配网页的 URL；普通 tabs 查询、创建、关闭与消息发送也不要求单独的 tabs 权限。因此不应把“使用了 chrome.tabs API”写成必须申请 tabs 的理由。1.0.1发布包已删除tabs；普通网页匹配、计时与受保护页提示由发布回归核验。[Chrome Tabs API 权限说明](https://developer.chrome.com/docs/extensions/reference/api/tabs#permissions)

## 隐私表单填写依据

扩展**会访问并在本机处理用户数据**。不能因为没有服务器，就选择或声称“完全不访问、使用或存储任何用户数据”。Chrome 官方明确，本机处理也需披露并提供隐私政策。[用户数据 FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)

| 表单事项 | 如实填写依据 |
| --- | --- |
| 网页浏览历史 / Web history | 需要披露：读取当前和打开标签页的网址用于规则判断；保存最近触发网址的来源和路径、触发时间，并在会话中暂存完整 URL。没有调用浏览器 history API，也不读取安装前的历史记录。 |
| 用户活动 / User activity | 需要披露：使用活动标签页、窗口焦点、锁屏状态及规则触发时间来计算前台浏览用时。无需记录键盘内容、鼠标点击轨迹或屏幕截图。 |
| 用户输入 | 保存用户自行填写的规则名、网址、例外、提醒文字和配置；具体页面规则可以包含查询参数和锚点。配置或 URL 自身可能含有个人信息，不能宣称其天然匿名。 |
| 网页内容 | 不抓取网页正文、表单值、消息、图片或音视频内容；内容脚本会显示提示，并尝试暂停当时页面中可找到的音视频元素。 |
| 远程代码 | 否。功能代码随扩展包提供，未发现远程脚本、动态下载执行、eval 或 new Function。 |
| 上传 / 出售 / 广告用途 | 当前版本没有遥测或数据上传接口，不出售数据，不用于广告、画像、信用或贷款评估。 |
| 隐私政策 URL | 必须填可公开访问的真实页面地址；政策正文位于同目录的《隐私政策.md》，本地路径不能代替公网 URL。 |

最终勾选以商店表单当时对数据类别的具体定义为准，上述事实应同时体现在商店说明、隐私政策和扩展界面中。[Chrome 隐私字段说明](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy) · [Edge 发布隐私信息](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension#step-6-enter-privacy-information)

## 审核测试说明

不需要账号、密码、付费或测试服务器。界面语言为简体中文。

1. 安装扩展，打开普通网页，例如 https://example.com 。
2. 点击工具栏中的「停一下」图标，选择为当前网站创建规则。
3. 选择「等待后放行」，设置等待 5 秒，关闭时段限制，不设置每日额度，启用并保存。
4. 回到该网页，应出现倒计时。结束后点击继续，可继续浏览；刷新当前地址不会重复等待。
5. 将规则改为「仅提醒」或「直接拦截」并保存，查看相应界面。
6. 在插件弹窗或管理页点击「放行 15 分钟」，该规则暂时停止处理；点击「结束放行」可立即恢复。其他符合条件的规则仍可能生效。
7. 在「触发记录」查看本机记录；在「设置与备份」导出配置 JSON。文件仅含规则，不含日志和每日用时。
8. 删除测试规则。浏览器设置页和扩展商店属于受保护页面，不用于测试规则遮罩。
