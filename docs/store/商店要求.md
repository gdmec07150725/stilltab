# Chrome / Edge 商店发布要求

核对日期：2026-10-14。本文按当前官方页面整理；账户状态尚未在后台核实。扩展功能依据本仓库 `apps/extension/manifest.json`、`apps/extension/src/background.ts`、`docs/设计与规则语义.md`。商店字段以实际后台校验为最终准据。

## 本次发布需要完成的项目

- 将产品名称、短描述、图标写入最终构建；上传 ZIP 的根目录直接包含 `manifest.json`，不套一层 dist 目录。不要把源码、node_modules、测试、浏览器配置文件或手机工程打包进去。
- 两家分别创建商店条目，分别上传同一份已验证的 MV3 构建（如果仅商店文案不同，无须拆源码）。
- 提供中文长描述、图标、实际功能截图、Chrome 小宣传图、单一用途、逐项权限理由、数据使用声明和公开可访问的隐私政策。
- 浏览器包只宣传网页功能：规则匹配、时段、每日额度、提醒、等待、遮罩拦截、临时放行、记录及配置导入导出。Android、iOS 功能不属于本扩展。
- 首装无已启用规则。审核测试说明应明确先创建测试规则，避免审核员误认为无功能。
- “拦截”必须描述为网页遮罩；不宣传“阻止网络请求”“不可绕过”“家长控制”或精准计费。这与现有实现边界相符。

## 名称、描述、分类和素材

通用 manifest：`name` 最多 75 字符；`description` 最多 132 字符；Chrome 商店要求 `icons`。工具栏同时配置 `action.default_icon`，建议准备 16、32、48、128 像素图标。[Manifest 要求](https://developer.chrome.com/docs/extensions/reference/manifest)

| 素材 | Chrome | Edge |
| --- | --- | --- |
| 商店图标 | 必需，128×128 PNG；方形主体约96×96，四周透明留白16px | 每语言必需，1:1，建议300×300，最低128×128 |
| 功能截图 | 必需1–5张；1280×800或640×400，无额外留白，直角 | 可选，最多6张；1280×800或640×480 |
| 小宣传图 | 必需，440×280 PNG/JPEG | 可选，440×280 |
| 大宣传图 | 可选，1400×560 PNG/JPEG | 可选，1400×560 PNG |
| 视频 | 先作为可选项；见下方文档差异 | 可选，YouTube URL |

本次统一输出 1280×800 的真实截图，可供两家复用；小宣传图表达品牌，截图展示实际功能，不把设计稿冒充截图。[Chrome 图片规范](https://developer.chrome.com/docs/webstore/images)

Chrome 还需详细描述、分类、语言。建议选择后台实际提供的“生产力/专注”相近分类；不要杜撰一个后台不存在的分类。网站、支持网址、经验证发布者网址均可后补。官方 listing 文档把 YouTube 链接列在“must”列表，但专门图片规范明确仅图标、小宣传图、截图必需；不将视频作为预先阻塞项，最后看后台校验。[Chrome listing 字段](https://developer.chrome.com/docs/webstore/cws-dashboard-listing)

Edge 每语言长描述必需，250–10000字符；名称和短描述来自 manifest，至少一个语言必填；类别必填。网站、支持联系方式、搜索词可选。上述 Edge 尺寸和字段见[Edge 发布流程](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension)。

Edge 商店文案不提其他浏览器；其隐私政策以 Microsoft Edge 为主体。建议隐私网站提供 `/chrome/privacy` 与 `/edge/privacy` 两个地址，内容的数据行为一致。名称/图标应原创、权利清晰，不仿冒现有扩展。[Edge 开发者政策 1.1.2、1.5.2、2.2](https://learn.microsoft.com/legal/microsoft-edge/extensions/developer-policies)

## 隐私政策与后台声明

**本扩展需要公开隐私政策 URL。** 仅本地处理并不免除披露：现有功能读取当前网址、记录触发时间与网页路径、累计用时并保存用户规则。Chrome FAQ 明确本地处理/存储也要披露，并且要提供隐私政策。不要将“无服务器、无上传”写成“完全不处理任何用户数据”。[Chrome User Data FAQ，第3、14条](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)

页面应明确这些实际行为（来自项目实现）：

- 规则、例外、自定义提醒文案和配置均在本机保存；用户主动填写的精确匹配网址可能含 query/hash。
- 当前标签页 URL、规则确认/等待状态和计时采样使用 session 存储；浏览器重启后清空。
- 本地保留最近8个有用时记录的日期及最多300条触发记录；触发记录只存 origin + pathname，不存 query/hash。
- 无账户、广告、分析 SDK、远程代码、云同步或开发者服务器；不上传、出售、共享用户浏览信息。
- 导出文件含规则，可能含用户自己填写的敏感网址；导出由用户主动发起并保存在其选择位置。
- 用户可在扩展中管理规则和记录；仅写入实际已经支持的清理入口。卸载扩展可删除浏览器中的扩展存储；用户自行导出的文件需自行删除。
- 数据只用于执行用户设置的网页访问规则、展示用时/触发记录；补充符合 Chrome User Data Policy 及 Limited Use 要求的声明。
- 指向真实的支持/联系入口，不使用编造邮箱或占位 URL。外部页面必须免登录可读。

后台“数据使用”建议按实际字段披露网页浏览记录（URL、域名、路径）、用户活动（用时/触发记录，若对应字段定义适用），并明确本地处理。网页内容类别应按最终代码和后台定义判断：当前只操作提醒/遮罩及暂停找到的 audio/video 元素，不抓取网页正文或表单内容。不要盲选所有敏感类别，也不要因无上传而全不选。

两家 Privacy 页均需单一用途、权限理由、远程代码和数据使用认证。MV3 最终包全部代码随包附带，因此远程代码项填“No”。Chrome 要求声明、隐私政策与真实行为一致。[Chrome Privacy 字段](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy) Edge 要求个人信息访问、传输或收集时提供可访问政策 URL；其数据声明同样要保持一致。[Edge Privacy 步骤](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension#step-6-enter-privacy-information)

## 可用于两家后台的单一用途与权限理由

单一用途：

> 根据用户自己设置的网页访问规则，在指定网站、路径或页面及时间条件下显示提醒、等待或拦截遮罩，帮助用户控制网页使用时间和减少分心；所有规则及用时记录在本机处理。

以下为基于当前源码的原创说明。若最终 manifest 移除某权限，随之删除该字段；不为未来功能预留权限。

| 权限 | 提交说明 |
| --- | --- |
| `storage` | 在本机保存用户创建的规则、例外、每日用时、触发记录及临时放行到期时间；保存当前浏览器会话的倒计时和确认状态，保证后台线程休眠后规则连续。 |
| `tabs` | 建议在发布前移除。现有HTTP/HTTPS主机权限已经提供普通网页的URL读取；多数tabs API本身不需要tabs权限。删除后验证弹窗、计时、切换和关闭标签行为，不应为冗余权限编写必要性理由。 |
| `scripting` | 安装或更新扩展后，向已经打开的普通HTTP/HTTPS页面注入随扩展打包的内容脚本，让现有页面获得规则提醒与遮罩功能。 |
| `webNavigation` | 识别单页应用的地址变化以及锚点导航，重新匹配规则，并清理只适用于上一完整网址的单次确认或等待状态。 |
| `alarms` | 定期唤醒MV3后台线程，重新检查时段、每日额度和临时放行到期，恢复应当生效的页面规则。 |
| `idle` | 感知系统锁屏，在锁屏期间暂停前台用时累计，避免把离开电脑的时间计入网页每日额度。 |
| `http://*/*`、`https://*/*` | 用户可为任意普通网站、路径或页面创建规则，扩展需自动在匹配页面读取网址并显示提醒、等待或拦截遮罩。规则在用户未点击工具栏时也要执行，所以单次activeTab授权不足。网站正文、表单和密码不会被采集或上传。 |

最小权限核查：API使用不等于需要同名权限。官方[Tabs API 权限说明](https://developer.chrome.com/docs/extensions/reference/api/tabs#permissions)确认，匹配的主机权限已允许读取url等敏感标签属性；本项目只处理HTTP/HTTPS，因此可以优先尝试移除 `tabs` 权限并验证。

代码证据：`background.ts` 使用上述 API；`content.ts` 在页面中展示界面并暂停当时找到的音视频。初始权限没有 cookies、history、webRequest 或 downloads；不用这些名称描述实际没有申请的权限。

## 提交、审核及上架控制

Chrome：上传包 → Store Listing → Privacy → Distribution → Test instructions → Submit for Review。可选择审核通过自动发布，或取消自动发布后手动上线；通过后最多30天需发布，否则退回草稿重新审核。[Chrome 发布流程](https://developer.chrome.com/docs/webstore/publish) 审核通常数天，也可能数周；广泛主机权限可能增加审核时间，超过三周可联系官方。不能承诺当天上架。[Chrome 审核流程](https://developer.chrome.com/docs/webstore/review-process)

Edge：上传 ZIP → Availability → Properties → Privacy → Store listings → 测试说明 → Publish。可公开或隐藏（隐藏仍可用直链安装），市场默认全部。当前官方流程说明提交后认证可达7个工作日，通过自动上架；没有在这篇官方流程中找到“审核通过再手动发布”的同等控制。[Edge 发布流程](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension#step-8-enter-certification-testing-notes-and-submit-the-extension)

推荐审核测试说明（不需要账号）：

1. 安装后打开一个普通HTTP/HTTPS网站；浏览器内部页面和扩展商店不可注入。
2. 点击工具栏图标，创建针对当前网站的规则，动作设为等待、5秒、全天、不使用每日额度门槛，启用并保存。
3. 返回网页，确认出现等待遮罩，倒计时结束后点击继续。
4. 将动作改为提醒或拦截，验证效果；使用15分钟临时放行并提前结束放行。
5. 打开管理页验证模板、规则预览、记录及配置导入导出。首装没有预设生效规则，用户需要创建规则。

## 实际阻塞项判定

研究不能代替账户后台检查；下列为需要核实的前置条件，而不是声称账户目前一定缺失：

- 用户尚未登录或未完成对应商店开发者注册、协议、费用/身份/邮箱/两步验证时，提交受阻；这是用户账户操作，不是编码问题。
- 没有真实、公开、可访问的隐私政策 URL 时，本项目不能完整提交。政策正文可先写完，再放到用户控制的网站或已授权托管地址。
- 包、图标、文案与素材可在等待上述步骤时全部完成；不要因可选视频、支持网址或宣传大图延误提交。
- 成功上传草稿不等于送审；送审成功不等于审核通过；只有商店正式页面可安装且后台状态已上线，才报告“已上架”。
