# 开发说明

## 本地命令

从仓库根目录开始执行。

需要 Node.js 20+ 与 npm（浏览器自动化使用的当前 Playwright 需要 Node 20+；仅构建和单元测试也曾在 Node 18.17 通过）。

```powershell
cd apps/extension
npm ci
npm run typecheck
npm test
npm run build
npm run test:browser
```

`npm ci` 使用 package-lock.json 锁定依赖。构建不依赖网络资源，输出 dist，可直接加载。TypeScript 编译目标 Chrome 120，使用 esbuild 打包独立脚本，不需要应用服务器。

## 代码地图

- src/core/types.ts：规则、存储和消息协议。
- src/core/engine.ts：链接匹配、时段、冲突、额度、用时分段和导入校验。
- src/core/defaults.ts：空白规则与四个显式添加的模板。
- src/runtime.ts：前台采样有效性、当前页状态和保留期限。
- src/background.ts：唯一状态写入方、Chrome API 事件、权限检查、持久化和状态广播。
- src/content.ts：网页内三种处理界面及每秒心跳。
- src/options.ts / popup.ts / ui.ts / styles.css：管理界面、弹窗、通用表单与样式。
- tests/*.test.ts：引擎和执行状态单元测试。
- tests/browser.mjs：在隔离用户目录启动真实浏览器，以本地 HTTP 测试页面验收扩展；不访问日常浏览器配置。

修改核心协议需同步检查所有调用方。任何影响计时的改动至少运行单元测试和真实浏览器测试。Playwright 浏览器测试期间会启动独立窗口，产物与配置目录保存在项目 work 下。

## 设计取舍

采用原生表单和少量共享 DOM 工具，不引入前端框架和远程依赖。配置、日志和用时在一个 local 键中由单一工作线程串行更新，session 存标签页执行状态；跨存储区域不具备数据库事务保证，异常终止可能丢失最后一个采样点。每次心跳落盘优先保证小规模本地版本的恢复能力。

测试重点是用户行为及边界，不承诺反绕过。对外发布前应补充 Chrome 手动安装验收、长时间稳定性与多站点兼容性、商店权限及隐私审查。首版未做发布操作。
